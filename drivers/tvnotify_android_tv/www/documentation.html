TvNotify for Android TV

Control4 room driver for the TvOverlay app

The room driver connects Control4 to one Android TV (the TV endpoint) running the TvOverlay app, using the app's REST API over plain HTTP. Add one room driver per TV endpoint. It can:

  • Show popup notifications and alerts on the TV endpoint, with title, message, icons, image and position.
  • Show camera snapshots and live streams from cameras in the project (Hikvision, Dahua / Amcrest, Foscam, Reolink, Axis or your own address formats), working out each camera's address and login itself.
  • Place fixed badges that stay in a corner of the screen until removed (or for a set time).
  • Change TvOverlay's overlay and notification settings (background dimming, clock, hot corner, notification behaviour).
  • Keep popups in the programmed order, and report the TV endpoint's Online / Offline state, results and counts as properties, variables and events for programming.
  • Work on its own, or as a member of the TvNotify Controller (several TV endpoints at once, profiles and the TV Notifications page).

Setup

Before you start

  • TvOverlay is installed on the TV endpoint and its setup is complete (permissions granted; the app opens without prompts).
  • The TV endpoint is already in the Control4 project with its own driver (for example the TV manufacturer's driver), and that driver has its IP address on its network connection.
  • Recommended: give the TV endpoint a DHCP reservation. If its IP address does change, the room driver picks up the new address from the TV endpoint's driver by itself (the next time a send gets no answer), or straight away when you press Refresh TV Driver List. This works as long as the TV endpoint's driver has the new address; an address entered in Manual IP Address (fallback) has to be updated by hand.
  • Requirement: Control4 OS 3.3.0 or later.

Step 1 - Add the room driver

In Composer, add TvNotify to the room the TV endpoint is in - one room driver per TV endpoint.

Step 2 - Link it to the TV endpoint

Under TV Connection:

  • TV Driver
    Choose the TV endpoint's driver from the list. The room driver reads the TV endpoint's IP address from that driver. If the TV endpoint was added after the room driver, press Refresh TV Driver List (Actions tab) first.
  • TV Port
    Leave at 5001 (TvOverlay's standard port) unless it has been changed in the app.

Step 3 - Check the connection

Press Send Test Notification (Actions tab). A popup appears on the TV endpoint and Status shows Online.

Note:
The room driver never changes the TV endpoint's TvOverlay settings by itself. They are only changed when you use Set Overlay, Set Notification Settings or the Overlay Background Off action. Settings are kept in the TvOverlay app on the TV, so they stay after a TV restart or a driver update.

Step 4 - If the IP address cannot be read

Some TV drivers do not share their address. Status then says so and the Manual IP Address (fallback) property appears: enter the TV endpoint's IP address there. Dump TV Driver Info (Actions tab) writes a report to the Lua Output window and the Control4 log if you need to see why.

Step 5 - Cameras (optional)

To show camera snapshots or live streams on the TV endpoint, review Camera Snapshots:

  • Default Vendor
    Leave at Auto Detect in most cases.
  • Address Method / Login Method
    Leave at Use Device's Own...: each camera's address, ports and login are then taken from the camera settings from within the project.

For a camera that is not in the project, type its full addresses into Snapshot URL / Stream URL in the Send Camera Notification action.

Step 6 - Next steps

  • Program notifications in Programming → Device Actions (see Programming commands).
  • To send to several TV endpoints at once, or to use profiles and the TV Notifications page, add the TvNotify Controller and connect this room driver to it.

Encode the Image to Base64?

  • Yes (default) - the room driver downloads the snapshot itself (answering Digest or Basic authentication), checks it is a real image, converts it to Base64 and sends it to the TV endpoint in the notification. Use this for cameras that need a login the TV endpoint cannot supply. Images over 3 MB are rejected (use the sub stream).
  • No - the room driver sends the snapshot URL to the TV endpoint and the TV endpoint downloads the image itself. If a login is available (see Camera addresses and logins) it is put into the URL as http://USER:PASS@host/.... No fetching, no authentication handshake and no Base64 conversion happens in the room driver. Only works if the TV endpoint's TvOverlay app can authenticate that way (Digest often fails; use Yes).

Camera addresses and logins

Every Control4 camera has standard camera settings in Composer: Address, HTTP Port, RTSP Port, Authentication Required, Username and Password (the settings Navigators use to show the camera). The room driver looks these up from within the project, whichever camera driver is used. For a camera viewed through an NVR they normally hold the NVR's address and login. They are read when the room driver starts, kept in memory, and read again every 10 minutes or when a camera is not found. Control4 stores the password Base64-encoded; the room driver decodes it. Dump Camera Info shows the settings on its CAMERA SETTINGS line and the login it would use on its LOGIN line (passwords hidden).

Login

The room driver uses the first login it finds:

  1. Device Actions: the NVR/Camera Username / Password fields of the Send Camera Notification action. They apply to that one action only and override everything else. The values are stored in plain text in the Composer program.
  2. Login Method:
    • Use Device's Own Credentials - the camera's own Username / Password looked up from within the project, when its Authentication Required is ticked (otherwise no login is sent). A typed Snapshot URL / Stream URL with no Camera chosen has no camera to take a login from.
    • Specify Below - the NVR/Camera Username / Password properties, for every camera.
  3. A login written into a Snapshot URL, Stream URL or URL Format (http://USER:PASS@host/...) is used as it is.

The debug output names the address and login used, for example address: camera settings 10.2.1.1, HTTP 80, RTSP 554 and login: camera settings (user Control4); passwords are never shown.

Upgrading from an earlier version: on the first start, if NVR/Camera IP Address was filled in, Address Method is set to Specify Below, and if a username / password was filled in, Login Method is set to Specify Below, so an existing system keeps working exactly as before. Switch them to Use Device's Own when you are ready.

The same login is used for every Camera Vendor, the Other Vendor formats, and the action's Snapshot URL and Stream URL, whether the room driver built the address or you typed it. How it is sent depends on the address:

Auto Detect

With Auto Detect (as the Default Vendor, or chosen in the action) the room driver recognises the vendor from the Control4 drivers themselves: the manufacturer, model and driver file name (for example a driver whose manufacturer is Hikvision). Recognised makes: Hikvision, Dahua / Amcrest, Foscam, Reolink and Axis.

  • Camera connected to an NVR whose make is recognised (Hikvision, Dahua / Amcrest or Reolink) and whose channel is found: addresses go through the NVR.
  • Otherwise the camera's own make decides, and the camera is reached directly at the address read from its driver.
  • Neither recognised (for example a generic camera driver that names no make): that output is left out and Last Result says so - choose the Camera Vendor in the action or set Default Vendor.

The order is: the action's Camera Vendor, then the Default Vendor property; Auto Detect is used wherever it is chosen. The debug output says which vendor and route were used and why, for example detected from the NVR's manufacturer 'Hikvision'. Run Dump Camera Info to see what the room driver reads for a camera (CAMERA DRIVER / NVR DRIVER lines).

Cameras not on the NVR

If the vendor is Hikvision NVR but the chosen camera has no NVR connection (for example an off-site camera that is in the project but not wired to the NVR), the room driver does not fail: it goes to the camera directly, using the camera's recognised make (Hikvision Camera if not recognised). Its address, ports and login are taken from the camera settings from within the project (see Camera addresses and logins). If its address cannot be read, type the camera's Snapshot URL / Stream URL in the action. The TV endpoint (for streams, and for snapshots with Encode = No) or the controller (snapshots with Encode = Yes) must be able to reach an off-site camera, for example over a VPN.

Placeholders for the two formats: {ip}, {port} (HTTP port in the snapshot, RTSP port in the stream), {channel} (1, 2 ...), {channel0} (0, 1 ...), {nn} (01, 02 ...), {code} (101 / 102 / 103 ... by Camera Stream), {subtype} (0 / 1 / 2 by Camera Stream), {user}, {pass}.

Mixed systems: set the property to the most common vendor and choose the other vendor in the action's Camera Vendor field (or use Auto Detect). If a camera's address cannot be read, that output is left out and Last Result says so - type that camera's addresses into the action's Snapshot URL / Stream URL. Other Vendor is chosen only as the Default Vendor, and actions use it through Use Default; the action's Camera Vendor list does not include it.

Live streams: TvOverlay plays RTSP (and HLS / DASH) streams, but Android TV players often cannot decode H.265 camera streams - set the camera's stream to H.264. Use the Sub stream for popups. How TvOverlay shows a popup with both a snapshot and a stream has not been tested.

Snapshot URL / Stream URL on the action (any other address). Used exactly as typed (plus the login - see Camera addresses and logins); the Camera, Output, Camera Vendor, channel lookup and NVR properties are ignored for that address. Snapshot example: http://192.168.1.60/snapshot.jpg. Both may use the placeholders {user} and {pass}.

Why the address is built here. Control4 does not let one driver read another driver's Composer properties, and an NVR driver publishes no address. The room driver therefore builds the addresses itself from the camera settings from within the project (or from the Specify Below properties), the camera's NVR connection and the chosen vendor.

If a snapshot does not appear: the popup is still shown (without the picture), Request Failed fires, and Last Result says why. Run the action Dump Camera Info (first camera) (Actions tab; lists every camera with its NVR link), or the command Dump Camera Info on a specific camera, (and the action Dump TV Driver Info for TV problems) and read the Lua Output window / Control4 log; it lists the connections, variables and NVR link the room driver can see (Composer properties of other drivers cannot be read), with passwords hidden.

Programming commands

In Programming → Device Actions → (this room driver). Each command's line in the Script screen is a short summary made from its Description field, for example Send Notification on Living Room TV: "Doorbell" (Title: Front door).

Note:
Description is only a label for the Script screen - the room driver does not send or use it. Without it, Composer would list every parameter of the command in the Script line, most of them empty. Leaving Description empty is allowed; the line then reads Send Notification on Living Room TV: "" (Title: Front door).

Tokens: Title, Message, Source and Fixed Message accept {TIME} {TIME12} {DATE} {DAY} {DATETIME} {DEVICE}, replaced when the command runs.
Icons: Material Design Icons names such as mdi:home.
Colours: Send Notification's small icon colour is chosen with Composer's colour picker - set Small Icon Color to Custom and pick the colour in Small Icon Custom Color (Use TV Default = the Default Small Icon Color property; the picker is then ignored). Send Fixed Notification's colours are typed as hex (#RRGGBB, or #AARRGGBB with transparency). Controller profiles take colours as hex, and older programming with a hex Small Icon Color keeps working.

Badge ClearedWhen a badge is removed from this TV (manually, by programming or on expiry)
Badge ExpiredWhen a badge is removed because its Expiration runs out (Badge Cleared fires too)

Badge events fire on every room driver that shows the badge. A Controller profile badge sent to three TV endpoints also fires the Controller's own badge events, so program against one level or the other, not both.

Tips

  • Re-using a Notification ID edits a popup that is queued or on screen; re-use a Fixed Notification ID to update a badge.
  • Dim the screen for a movie: Set Overlay with Background Visibility 60; undo with the action Overlay Background Off.
  • Requests are queued and sent one at a time, in order.
Note: badges and the clock
Out of the box, TvOverlay shows badges at the same visibility as its clock. So if Set Overlay sets Clock Visibility to 0, badges disappear too. To hide the clock but keep badges, use Set Notification Settings with:
  • Display Fixed Notifications = On
  • Fixed Notification Visibility = 95 (or any value above 0)
Badges then keep their own visibility, whatever the clock is set to.
